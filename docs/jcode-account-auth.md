# jcode 계정 인증 수정본

이 문서는 콕핏의 AI 계정과 jcode 인증 저장소를 연결하는 안전장치를 기록합니다. 기존 배포의 CLI 프로필은 유지하고, 새 계정별 jcode 경로는 별도 엔진 설치 후 명시적인 로그인 버튼으로 시작합니다. 소스 변경과 후보 빌드만으로 실행 중인 작업자나 공용 jcode daemon이 바뀌지는 않습니다.

기존 CLI 계정의 기본 버튼과 추천 버튼은 저장된 Claude Code·Codex 로그인으로 새 세션을 엽니다. jcode 엔진이 설치됐다는 이유로 새 인증을 요구하지 않습니다. 별도 격리 환경을 만들 때만 `jcode 연결 · 별도 로그인`을 선택합니다. 이미 jcode 인증을 사용하는 계정은 계속 jcode로 열며, 인증 오류가 나도 다른 CLI 저장소로 우회하지 않습니다.

## 기준과 변경 범위

- upstream `1jehuang/jcode` 0.91.0, commit `d2ffcd62c9bc540dd913a046d62cdc0307b5e189`.
- 인증 패치: `patches/jcode-0.91.0-auth-safety.patch`.
- 계정 비용 패치는 `patches/jcode-0.91.0-account-usage.patch`로 별도 보관합니다.
- 계정별 격리 모드는 `patches/jcode-0.91.0-native-account-mode.patch`입니다. 비용, 인증 안전장치, 격리 모드 순서로 적용합니다.
- Claude `auth.json`과 OpenAI `openai-auth.json`의 형식은 유지합니다. 토큰을 다른 저장소로 이관하지 않습니다.
- 모든 native 인증 파일 수정은 읽기부터 저장까지 소유자 전용 sidecar 파일의 OS 잠금으로 직렬화합니다. 공급자 토큰 갱신은 계정별 별도 잠금으로 여러 프로세스가 중복 수행하지 않도록 합니다.
- 갱신 결과는 관측했던 refresh token이 저장소에 남아 있을 때만 반영합니다. 재로그인·삭제·라벨 재사용을 감지하면 오류로 종료하며 다른 계정 토큰을 반환하지 않습니다.
- 처음부터 native 계정이 없던 기존 외부 Claude 인증 경로는 유지합니다. 외부 자격정보가 여전히 일치하고 native 저장소가 비어 있을 때만 최초 갱신 결과를 저장합니다.

## 기존 계정 재인증

새 숨김 옵션 `login --provider claude|openai --account <label> --expected-email <email> --no-validate`는 선택한 기존 계정만 재인증합니다. provider 생략과 `auto`, scriptable 로그인 옵션 조합은 거절합니다.

브라우저를 열기 전에 저장된 계정의 이메일을 검증합니다. OpenAI는 이때 워크스페이스 ID도 고정합니다. 인증 후 공급자 응답의 이메일·워크스페이스와 저장 직전 계정 정보를 다시 비교합니다. 다른 계정으로 로그인하거나 선택 계정이 변경되면 기존 인증 파일을 보존합니다.

이 경로는 기본 계정·기본 공급자를 변경하지 않고 실행 중인 daemon에 `AuthChanged`를 보내지 않습니다. 유료 모델을 사용하는 로그인 후 검증도 실행하지 않습니다. OAuth 성공은 실제 모델 요청이나 도구 실행의 성공을 의미하지 않습니다.

## 적용과 되돌리기

1. 위 commit의 깨끗한 소스에 세 패치를 적용하고 기본 feature로 빌드합니다. 패치 적용·역적용 가능 여부를 먼저 검사합니다.
2. 실제 계정이 없는 임시 HOME·JCODE_HOME에서 CLI 거절 경로와 별도 daemon ping을 검증합니다.
3. 새 엔진은 콕핏 데이터 폴더의 `jcode-engine/jcode`에 설치합니다. 공용 launcher와 실행 중인 daemon을 교체하지 않습니다. 계정별 새 홈은 `jcode-profiles/<등록 ID>/.jcode`이며 계정마다 소켓도 분리합니다.
4. `jcode 연결 · 별도 로그인`의 최초 클릭은 이메일과 선택한 OpenAI 워크스페이스만 고정한 빈 계정을 준비합니다. 기존 CLI의 refresh token은 복사하지 않습니다. 사용자가 브라우저 인증을 마치면 같은 계정 행에서 새 작업 세션을 엽니다. 취소하거나 다른 계정으로 인증하면 다른 CLI 인증으로 우회하지 않습니다.
5. 잔여량 HTTP 조회는 콕핏이 수행하고 native 토큰 갱신은 해당 계정의 jcode 엔진만 수행합니다. `cockpit-account` 명령은 고정된 capability 또는 갱신 결과 코드만 출력하며 토큰을 반환하지 않습니다.
6. 기존 작업자는 그대로 유지합니다. 사용자가 계정 전환을 요청한 경우에만 빈 입력창, 종료, 닫힌 snapshot을 확인한 뒤 같은 대화를 대상 계정에 연결합니다. 이미 거절된 로그인과 다른 제공자는 원래 대화를 종료하기 전에 차단합니다.

native 모드에서는 환경 API 키와 다른 CLI 저장소로의 인증 fallback을 차단합니다. 글로벌 설정과 MCP 항목은 처음 준비할 때 인증 항목을 제외하고 가져옵니다. 스킬·플러그인·지침은 명시한 설정 경로만 연결하고 OAuth 디렉터리 전체를 공유하지 않습니다. jcode 내부의 별도 창 생성과 SSH 이동은 계정 환경을 잃을 수 있어 거절하며 콕핏의 새 세션 버튼을 사용합니다.

새 격리 경로의 배포·실제 브라우저 인증 상태는 `docs/_local/jcode-native-accounts/progress.json`과 검증 결과를 확인해야 합니다. 이 문서가 엔진 적용이나 실제 모델 요청의 성공을 증명하지는 않습니다.

되돌릴 때는 작업을 인계하고 이전 바이너리로 전환합니다. 공급자가 refresh token을 회전했을 수 있으므로 과거 인증 파일을 복원하지 않습니다. 비밀번호·토큰을 패치, 검증 결과, 평문 백업에 저장하지 않습니다.

## 검증 범위

`jcode-base`의 `cargo test --release -p jcode-base auth:: --locked --offline --jobs 1`에서 412개 테스트가 통과했습니다. 여기에는 인증 회귀 15개와 처음 실행하는 빈 홈 디렉터리 검증이 포함됩니다. 로컬 모의 서버 바인딩이 가능한 환경에서 실행하며 실제 공급자 로그인과 모델 호출은 하지 않습니다.

독립 소스 검수에서 발견한 guarded auto 우회, 라벨 재사용, OpenAI 워크스페이스 변경 경합, 외부 Claude 갱신 회귀를 수정했습니다. 집중 재검수에서는 남은 고위험·중위험 문제를 확인하지 못했습니다. 실제 브라우저 인증, 콕핏 UI 연결, 구버전 writer와의 운영 전환은 별도 검증 대상입니다.

최종 기본 feature release 빌드도 통과했습니다. `scripts/verify-jcode-auth-safety.mjs <바이너리 절대경로>`는 실제 자격정보가 없는 임시 홈에서 CLI 거절 경로 7개를 실행하고 인증 파일과 기본값의 보존을 확인합니다. 별도 임시 daemon의 ping 응답과 종료도 검증했으며 실제 모델 요청이나 기존 세션 입력은 하지 않았습니다. 이 검증은 성공한 브라우저 재인증과 콕핏 UI 연동을 대신하지 않습니다.
