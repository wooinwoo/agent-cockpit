## Design Specificity Verdict

Cockpit 전용으로 강하게 저작된 화면이다. 번호 세션, 공간형 터미널 프레임, 페어 표시, 실시간 현황판, 메모/체크리스트, 무광 그래파이트와 계기판형 타이포는 일반 대시보드에 그대로 옮길 수 없는 제품 고유 언어를 만든다.

다만 기본 구성이 “터미널을 99% 사용하는 작업대”보다 “여러 터미널을 관제하는 벽”에 가깝다. 제품의 고유성은 충분하며, 다음 단계는 더 꾸미는 것이 아니라 활성 터미널의 권위를 높이고 주변 정보의 책임을 분리하는 것이다.

자동 검사는 `index.html`에서 8건을 찾았다: `design-system-font-size` 4건, `design-system-radius` 2건, `design-system-color` 1건, `flat-type-hierarchy` 1건. 대부분 토큰 드리프트에 대한 advisory이고, 6px overlay radius는 DESIGN.md 본문이 허용하므로 오탐 가능성이 있다. 8px radius와 `#fff`는 실제 토큰 이탈이다.

브라우저 오버레이는 임시 detector 서버가 권한 경계에서 시작되지 않아 제공되지 않았다. 대신 실제 렌더링 계측으로 109개 텍스트 중 2개 대비 실패, 101개 인터랙션 중 8개가 한 변 24px 미만, 이름 없는 포커스 가능 컨트롤 0개, 문서 수평 오버플로 0개를 확인했다.

## Priority Issues

### P1 — Cockpit이 터미널 네이티브 Ctrl 단축키를 가로챔

실제 전역 핸들러가 터미널 뷰에서도 Ctrl+T, Ctrl+R, Ctrl+B, Ctrl+W, Ctrl+F 등을 Cockpit 액션으로 사용한다. 라이브 터미널이 자체적으로 안내하는 Ctrl+T 같은 명령과 충돌하며 readline, tmux, TUI의 일반 조작도 깨질 수 있다.

**왜 중요한가:** 제품 사용 시간의 99%를 차지하는 터미널의 예측 가능성을 파워 유저에게서 빼앗는다.

**수정:** `.xterm` 포커스 중에는 평범한 Ctrl 조합을 기본적으로 터미널에 통과시킨다. Cockpit 액션은 leader chord, Alt/Meta, Ctrl+Shift 계열로 옮기고 하나의 재매핑 가능한 command registry에서 핸들러·도움말·title·`aria-keyshortcuts`를 모두 생성한다.

**Suggested command:** `$impeccable harden`

### P1 — 캔버스가 기본 운영 화면인데 활성 터미널의 지배력이 약함

1440×900에서 여러 터미널, 세션 탭, 약 380px 현황판, 툴바가 동시에 경쟁한다. 사용자가 원한 “한 화면씩 크게 보고 단축키로 넘기기”보다 overview가 기본이 된다.

**왜 중요한가:** 글자가 작아지고 움직이는 출력을 더 많이 스캔하며, 현재 입력 대상 확인에 지속적인 주의를 쓴다.

**수정:** 활성 터미널을 사용 가능 영역에 가득 채운 Focus 상태를 기본 운영 상태로 만든다. 캔버스는 잠깐 보는 overview로 두고, 프레임 Enter/더블클릭으로 Focus, Escape로 원래 캔버스 좌표에 복귀하게 한다. Focus에서는 현황판을 자동 접는다.

**Suggested command:** `$impeccable layout`

### P2 — 같은 세션 상태가 세 군데에 중복됨

동일한 세션이 상단 탭, 공간 프레임, 우측 현황판에 모두 표시된다.

**왜 중요한가:** 사용자가 세 표현을 계속 대조하게 되고 활성 세션 강조가 희석된다.

**수정:** 탭은 전환+점 하나, 캔버스는 공간 관계+페어, 현황판은 선택 세션의 상세 또는 waiting/error 예외만 담당하게 한다. 정상일 때 현황판은 자동 접고 예외가 생기면 펼친다.

**Suggested command:** `$impeccable distill`

### P2 — 단축키 도움말이 실제 제품과 드리프트함

현재 overlay는 Ctrl+4를 Jira, Ctrl+5를 CI/CD로 쓰지만 실제 핸들러는 Ctrl+4 PR, Ctrl+5 Jira, Ctrl+6 CI/CD다. 캔버스 핵심 조작도 작은 툴바 문구에만 있고 도움말에 빠져 있다.

**왜 중요한가:** 틀린 도움말은 없는 도움말보다 나쁘며, 잘못된 근육 기억을 만든다.

**수정:** 단일 command registry에서 실제 핸들러, overlay, command palette, title, README 표를 파생한다. Canvas 섹션에는 focus/overview, 전후 세션, pair/unpair, 방향 전환, pan, move, resize, fit을 넣는다.

**Suggested command:** `$impeccable clarify`

### P2 — 미세 글자·상태색·작은 타깃이 접근성을 갉아먹음

브라우저 계측에서 메모 하단 `Saved locally`와 `Local`은 8.7px, 대비 3.80:1이었다. 다섯 프레임의 주제 버튼은 높이 11.8px였고, 체크리스트 Copy ID는 15.9px, Reopen/Delete는 약 23.5px였다. 상태 점은 색 우선이며 assistive technology에 숨겨진 경우가 있다.

**왜 중요한가:** 저시력·피로 상태·정밀 포인팅이 어려운 사용자가 상태를 놓치거나 잘못 누른다.

**수정:** 지속 chrome은 최소 11–12px, 중요 desktop 타깃은 최소 28–32px, 모바일은 44px를 유지한다. 상태는 활성 프레임에서 짧은 텍스트와 live region을 제공하고 페어 관계는 색 외에 아이콘/라벨로 중복 인코딩한다.

**Suggested command:** `$impeccable audit`

## Persona Red Flags

**Alex — 파워 유저:** Alt Q/W, 번호 이동, 페어링과 팔레트는 좋아하지만 Ctrl+T/R/B/F 충돌을 즉시 겪는다. 도움말이 실제 키맵과 달라 학습할수록 위험해지고, overview↔진짜 full Focus를 오가는 한 키가 명확하지 않다.

**Sam — 키보드/저시력 사용자:** skip link, visible focus, semantic tab, ARIA 이름, reduced motion은 좋은 기반이다. 반면 절대 배치 캔버스는 200% 확대 시 읽기 순서가 중복되고, color-first 상태 점과 8.7px 보조 문구, 24px 미만 컨트롤이 장벽이 된다.

**Riley — 스트레스 테스터:** 같은 프로젝트명이 여러 개일 때 빈 주제가 `주제 추가`로 반복돼 번호에 의존한다. 긴 이름·주제의 ellipsis에는 전체값을 보는 확실한 경로가 필요하다. 모바일 세션 행의 가로 스크롤 위치가 중간에서 복구되면 시작점과 추가 버튼이 숨을 수 있다.

## Minor Observations

- 모든 프레임의 빨간 CLOSE가 항상 보여 파괴적 액션이 지나치게 높은 시각 우선순위를 갖는다.

- working, waiting, input needed, done, idle 어휘를 하나의 상태 용어 체계로 통일할 필요가 있다.
