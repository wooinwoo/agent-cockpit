# 전체 현황

전체 현황은 여러 세션의 목표, 최근 작업 보고, 다음 작업, 체크리스트를 한 목록에서 확인하는 운영 화면입니다. Operate 모드로 기존 [Instrument Bench 디자인](../DESIGN.md)을 유지합니다. [제품 원칙](../PRODUCT.md)의 터미널 중심 작업을 보조하며, 별도의 디자인 체계를 만들지 않습니다.

## 사용법

1. 탐색 메뉴에서 **전체 현황**을 엽니다.
2. **전체**, **확인 필요**, **실행 중**, **완료 작업**, **목표 완료**로 목록을 좁힙니다. 필터 숫자는 전체 세션에서 해당 조건에 맞는 수입니다.
3. 세션 행을 눌러 공유 세션 관리 패널을 엽니다. **목표·설정**, **체크리스트**, **진행·근거**에서 내용을 확인하거나 수정합니다. 자세한 조작은 [세션 관리](session-management.md)를 참고하세요.
4. **목록으로**를 누르면 상세 패널이 닫히고 선택했던 행으로 키보드 초점이 돌아갑니다. **새로고침**으로 즉시 다시 조회할 수 있습니다.

## 목록과 상태

각 행은 세션 이름과 역할, 우선순위, 현재 목표, 수행한 일, 다음 작업, 막힌 이유, 체크리스트 완료 수, 상태와 최근 보고 시각을 보여줍니다. 검증 근거 전문은 세션 관리의 진행·근거에서 확인합니다. 활성 터미널과 감독 설정에 남아 있는 세션을 함께 표시하며, 연결되지 않은 세션에는 **세션 연결 없음**을 표시합니다.

확인이 필요한 행을 먼저 배치합니다. 같은 그룹에서는 완료 확인된 행을 뒤로 보내고, 우선순위 높음·보통·낮음 순으로 정렬합니다. 조건이 같으면 세션 이름순입니다. **확인 필요**에는 연결 없음, 막힘 사유, 5분 이상 새 진척 없음, 완료 검증 대기, 승인·로그인 확인이 포함됩니다. 자동 지시 정지나 사용자 대화 중이라는 이유만으로 이 필터에 포함되지는 않습니다.

큰 상태 배지는 현재 AI 화면 관측을 기준으로 실행 중·입력 대기·승인 대기·AI 실행 안 됨을 구분합니다. 저장된 진행·완료 보고와 보고 시각은 별도로 표시합니다. 관측이 15초를 넘기면 오래된 자료로 표시하며 실행 중 집계에서 제외합니다. 실행 중 표시는 진척이나 목표 완료의 증거가 아닙니다. 화면 조회에 실패해도 관측 만료 판정은 계속 적용합니다.

체크리스트 수치와 막대는 해당 세션의 일반 작업 항목만 집계하며 질문 항목은 제외합니다. 모든 체크리스트를 완료해도 목표 완료 검증을 대신하지 않습니다. **목표 완료** 필터는 완료 상태인 작업자와 감독 세션을 모읍니다. 다음 작업은 보고에 기록된 다음 행동을 우선 표시하고, 없으면 첫 미완료 체크리스트 항목을 표시합니다.

완료한 체크리스트가 있으면 세션 행 아래에 **완료한 작업**과 최근 갱신된 완료 항목의 내용을 표시합니다. 펼치면 저장된 완료 항목 전체를 최신 갱신순으로 볼 수 있습니다. 항목 ID와 기록이 있는 경우 갱신 시각을 함께 표시하고, 자동 조회 후에도 펼침 상태와 키보드 초점을 유지합니다. **완료 작업** 필터는 완료한 체크리스트가 하나 이상 있는 세션만 표시합니다. 보관 범위는 기존 세션별 최대 50개 정책을 따릅니다.

## 작업자 자동 진행

상단 **자동 진행·승인 설정**을 펼치고 **작업자 자동 진행**에서 감독별로 선택합니다. 설정을 접어도 독립 진행·감독 연동 그룹 수와 승인 스크립트 상태 요약이 보입니다. **감독과 함께 운영**은 기존 동작을 유지합니다. **독립 진행 켜짐**은 감독이 중지되거나 응답하지 않아도 작업자가 저장된 목표를 이어가게 합니다. **자동 진행 일시정지**는 새 자동 지시만 멈추고 실행 중인 작업은 유지합니다.

개별 작업자 일시정지, 사용자 대화 보호, 승인·로그인, 운영 종료 시각은 독립 진행에서도 유지됩니다. 감독을 중지해도 독립 진행의 종료 시각은 지워지지 않습니다. 완료 보고는 감독의 검증 전까지 완료 확정으로 표시하지 않습니다. 서버 재시작 후에도 저장된 모드를 사용합니다. 다른 화면에서 모드를 바꾸면 오래된 저장 요청을 거절합니다.

작업자는 중간 보고 후 감독의 답변을 기다리지 않고 다음 미완료 작업을 이어갑니다. 서버는 모델 호출 없이 상태를 조회하고, 빈 입력창이 15초 이상 유지되면 새 작업·관련 답변·공급 결과·구체적인 배정 변경을 한 번 전달합니다. 같은 작업의 상태 확인, 시간 경과와 서버 재시작은 재전송 사유가 아닙니다. 감독도 확인을 마친 뒤 입력이 바뀔 때만 다시 점검하며, 미응답 점검을 반복 전송하지 않습니다. 실제 실행 중인 명령을 강제 종료하거나 같은 외부 작업을 중복 실행하지 않습니다.

세션 관리의 **체크리스트**에서 항목별 **실행 가능**, **진행 중**, **막힘**, **완료**를 선택합니다. 막힘에는 필요한 결과와 실제 작업·질문 ID를 연결합니다. 연결된 답변이나 공급 결과가 바뀌면 실행 가능한 상태로 풀립니다. 답변 도착은 실행 권한을 대신하지 않습니다. 미완료 실행 가능·진행 중 항목이 남아 있으면 전체 작업자 대기를 거절하며, 미완료 항목이 있으면 작업자와 감독의 완료 보고도 거절합니다. 오래된 대기 편집은 새 상태를 덮어쓰지 못하고 작성 중 입력을 유지합니다.

전체 대기 전에 본인 참고 경로와 인계 자료에서 허용된 직접 조사·미구현 코드·새 검증을 확인합니다. 새 자료가 전달되지 않았다는 이유만으로 독립 작업을 멈추지 않습니다. 전부 막혔으면 조사한 실제 경로와 조건별 의존성을 보고하고 감독이 이를 한 번 검토합니다. 전달 실패는 대기 상태와 구분해 재시도합니다. 5분 정체는 최근 실제 근거 또는 새 작업 전달 이후부터 계산하고, 같은 상태에서는 작업자 확인과 감독 개입을 한 번만 요청합니다. 등록 작업을 남긴 채 입력 대기로 끝난 작업자는 감독 없이도 짧은 자체 진단을 한 번 받습니다. 진단 입력이 거절되면 진단만 재시도하고 전체 목표는 재전송하지 않습니다. 등록되지 않은 목표의 독립 작업 가능 여부와 근거의 진위는 여전히 AI의 조사·검증이 필요합니다.

작업자 보고의 `artifact`, `version`, `result`를 함께 기록하면 감독 확인 전에도 새 진전으로 관측하고, `nextAction`은 다음 작업에 표시합니다. 동일 결과물·버전의 반복 보고나 상태 문구만 바꾼 보고는 진전 시간을 갱신하지 않습니다. 작업자 보고 근거와 감독이 확인한 검증 근거는 상세에서 구분하며, 새 동료 결과가 생기면 막힌 작업자가 감독 취합을 기다리지 않고 의존성을 다시 확인합니다.

여러 감독 기록에 같은 작업자가 남아 있으면 현재 자동 진행 중인 배정을 우선 표시합니다. 세션 관리에서 다른 과거 배정을 직접 선택해 조회할 수도 있습니다.

## 승인 스크립트 관리

**자동 진행·승인 설정**에서 기존 승인 스크립트의 실제 프로세스 상태, 대상 세션, 스크립트 동작 간격, 마지막 상태 기록과 입력 횟수·승인창 사라짐 횟수를 확인합니다. **스크립트 중지**는 확인창을 거쳐 기존 전용 승인 프로세스만 중지합니다. 실행 중인 AI 세션의 작업은 유지합니다. 상태를 확인할 수 없거나 로컬 접속이 아니면 중지 버튼을 비활성화합니다. 오래된 조회 응답이 중지 결과를 덮어쓰지 않도록 처리합니다.

이 화면은 승인 스크립트를 시작하거나 승인 키를 보내지 않습니다. 승인 내용을 확인하지 않고 통과시키는 재시작 기능은 제공하지 않으며, 자동 실행 허용 범위는 CLI 권한 설정에서 관리합니다. 표시하는 기록 시각은 마지막 승인 시각이 아니라 스크립트의 마지막 상태 기록 시각입니다.

## 세션·메모리 관리

터미널의 **세션 목록**에서 각 행의 **계정** 버튼을 누르면 **AI 계정** 목록의 기본 로그인 계정에 초점을 맞춥니다. 계정 행에는 해당 세션 이름을 붙이고, 다른 계정 행의 **ai1에 전환**처럼 세션 이름이 적힌 버튼을 누르면 그 세션으로 전환합니다. 상단의 별도 세션 선택창은 없습니다. 계정에 표시된 다른 세션을 누르면 그 세션의 기본 로그인을 확인합니다. **기본 로그인**은 저장된 선택이며 실제 연결 계정과 다를 수 있고, **실행 설정**은 세션을 열 때 지정한 계정입니다. 계정 추가와 새 터미널 설정은 접힌 항목을 펼칩니다. 전체 현황의 세션·메모리 관리에서는 선택한 세션 행 안에 계정 전환을 펼칩니다. 세션 목록을 갱신하거나 전환하는 동안 대상 변경을 막으며, 선택한 세션이 종료되면 이전 계정 선택을 닫습니다.

상단 **세션·메모리 관리**에서 열린 세션의 상태·최근 출력 시각·프로세스 메모리를 확인합니다. **보관 기록**에서는 종료한 세션의 마지막 출력 조회, 저장된 AI 명령으로 다시 열기, 보관 출력 삭제를 제공합니다. 다시 열어도 세션 ID·목표·체크리스트는 유지되지만 AI 대화는 해당 CLI의 기록 선택이 필요할 수 있습니다. 보관 출력 삭제는 목표·체크리스트를 삭제하지 않습니다.

프로세스 종료가 확인된 세션만 보관·재개 버튼을 활성화합니다. AI가 종료되어도 셸이 살아 있으면 자동으로 죽은 세션으로 판정하지 않습니다. 작업을 마무리한 뒤 기존 터미널 닫기를 사용하면 출력이 보관됩니다. 종료 의도는 프로세스를 닫기 전에 저장하므로 저장에 실패하면 세션을 닫지 않습니다.

**잔여 프로세스**는 종료한 콕핏 세션의 소유가 확인된 고아 MCP만 정리합니다. 실행 후 10분 이내, 활성 세션, 확인할 수 없는 조상·소유권은 제외합니다. 자동 점검은 서버 시작 약 5분 뒤부터 30분 간격이며, 종료 직전에 프로세스 시작 시각과 소유권을 다시 검사하고 PID 파일 디스크립터로 SIGTERM을 보냅니다. 좀비는 RSS 0이며 부모 작업을 강제 종료하지 않습니다. 메모리 합계는 공유 페이지를 중복 집계할 수 있습니다.

jcode 행의 **계정 전환**은 콕핏에 등록된 Claude·Codex 로그인과 jcode 자체 저장 계정을 보여줍니다. 현재 모델과 같은 제공자의 계정을 선택하고 **선택 계정으로 전환**을 누릅니다. 콕핏 등록 계정을 처음 선택하면 전용 jcode 계정 저장소를 만들고 현재 대화를 저장한 뒤 같은 대화 ID로 다시 연결합니다. 이후에는 기존 세션에 `/account <provider> switch <label>`을 전달합니다. 목표·체크리스트·터미널 ID는 유지하고 모델·제공자는 바꾸지 않습니다. 선택한 제공자의 공용 기본 계정도 바뀌므로 같은 jcode 서버의 다른 세션도 이후 인증 갱신 시 영향을 받을 수 있습니다. 기본 표시는 저장된 기본값이며 현재 세션의 연결 계정과 다를 수 있습니다.

빈 입력창에서는 한도 오류 이후에도 계정을 전환할 수 있습니다. 작업 실행·승인창·작성 중인 입력·사용자 대화 보호 중에는 전달하지 않습니다. 첫 연결에서는 로컬 단독 연결과 저장 완료도 확인하며, 실패하면 가능한 경우 원래 대화를 다시 엽니다. 화면의 명령 전달 안내와 실제 인증 성공은 별개이므로 터미널 결과를 확인하고 멈춘 작업을 재개합니다. 등록된 OAuth를 재사용하므로 정상 로그인은 웹 인증을 반복하지 않습니다. 인증이 취소되었거나 갱신이 거절된 계정은 재로그인이 필요합니다.

전용 저장소는 콕핏 데이터 폴더의 `jcode-accounts`에 생성하며 폴더는 0700, 인증 파일은 0600 권한으로 저장합니다. 기존 CLI 인증과 실행 중인 jcode 저장소는 덮어쓰지 않습니다. 최초 연결 시점의 등록 계정을 가져오며, 기존 전용 저장소에 새 계정을 자동 병합하지 않습니다. 토큰은 API·로그·문서에 출력하지 않습니다. 이 기능은 Linux/WSL Rust 실행기의 로컬 접속에서 제공합니다.

## 갱신과 실패

서버는 데이터 폴더의 `recovery-history`에 최신 복구본 `latest.json`, 사람이 읽는 `작업요약.txt`, 시간대별 복구본을 저장합니다. 기본 데이터 폴더는 Linux의 `~/.local/share/cockpit`, Windows의 `%LOCALAPPDATA%/cockpit`입니다. 최신본은 세션 저장 시 갱신하며 자동 저장 간격은 30초입니다. 시간대별 파일은 UTC 기준 해당 시간의 첫 저장본이고 최근 50개를 유지합니다. 목표·완료 조건·우선순위·체크리스트·질문과 답변·작업 보고·세션 배치·프로젝트 등록 정보를 포함합니다. 인증 파일, 터미널 출력과 대화 원문은 별도 복사하지 않습니다.

일반 재부팅은 콕핏을 다시 실행하면 원래 설정에서 복구합니다. 세션 고정 ID는 tmux가 없는 환경에서도 유지하며, 하루 이상 꺼 두었다는 이유로 기록을 폐기하지 않습니다. 기본 AI 실행 명령과 단일 옵션은 다시 실행하지만, 예전 배포 명령이나 임의 사용자 명령은 재실행하지 않습니다. 컴퓨터 전원이 꺼질 당시 명령의 실행 결과는 자동으로 성공 처리하지 않습니다. 손상된 데이터의 수동 복구는 `scripts/cockpit-history.mjs`로 복구본을 새 폴더에 내보내고 생성된 안내를 따릅니다. 실행 중인 서버 데이터를 직접 덮어쓰지 않습니다.

화면이 활성화되어 있고 브라우저 문서가 보이는 동안 5초마다 보드, 터미널 목록, 요약, 승인 스크립트 상태를 조회합니다. 진행 중인 조회가 있으면 중복 요청을 건너뜁니다. 마지막 성공 시각을 표시하며, 보드나 터미널 조회가 실패하면 **연결 확인 필요**와 함께 이전 자료를 유지합니다. 첫 조회부터 실패하면 자료를 불러오지 못했다고 알립니다. 요약 조회만 실패하면 이전 요약을 유지하면서 나머지 자료를 갱신합니다. 승인 스크립트 조회만 실패하면 목록 갱신은 계속하고, 승인 상태를 **상태 조회 불가 · 로컬 연결 확인**으로 표시하며 중지 버튼을 비활성화합니다.

## 화면 구성과 가독성

넓은 화면에서는 세션·역할, 작업 내용, 완료 항목, 상태의 네 열을 사용합니다. 세션을 선택하면 오른쪽에 공유 관리 패널을 열고 목록을 압축합니다. 너비 1000px 이하에서는 상세를 열 때 목록을 숨겨 같은 공간을 사용합니다. 600px 이하에서는 상세에 집중할 수 있도록 화면 제목과 필터도 숨기며, **목록으로** 버튼으로 복귀합니다. 모바일 필터는 가로로 스크롤하는 한 줄이고 주요 버튼은 높이 44px 이상입니다. 모바일 세션 행은 위쪽에 세션·상태, 가운데에 목표·최근 보고·다음 작업·막힘, 아래에 체크리스트를 배치합니다. 설정은 기본적으로 접어 업무 목록이 먼저 보이게 합니다.

무광 graphite 표면, 얇은 구분선, 기존 서체와 색상 변수를 그대로 사용합니다. 선택은 steel blue, 주의 상태는 amber, 실행 중과 완료는 green으로 구분합니다. 평평한 표면과 4px 모서리를 유지하며 장식용 `WORKSPACE`·`SESSIONS` 상단 라벨은 두지 않습니다.

전체 현황의 지역 가독성 선택으로 메타데이터와 상태는 12px, 작업 본문과 안내는 13px, 목표는 14px, 세션 이름은 18px을 사용합니다. 제목은 26px이며 모바일에서는 23px입니다. 데스크톱 완료 수는 20px, 필터 숫자와 모바일 완료 수는 14px이며 고정폭 숫자로 비교를 돕습니다. 작업·다음 행동·막힘 문구는 목록에서 최대 두 줄로 표시하므로 자세한 내용은 관리 패널에서 확인합니다. 버튼에는 키보드 초점을 표시하고 선택 상태를 접근성 속성으로 전달합니다.
